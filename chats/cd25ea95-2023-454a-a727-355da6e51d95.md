## DeepSeek Thinking Mode Token 计费规则

### 1. `completion_tokens` 确实包含两部分

在 thinking mode 下，API 响应的 `usage` 对象中：

```
completion_tokens = reasoning_content 的 token 数 + content 的 token 数
```

两部分 **合并计费**，没有单独的免费中间步骤。

### 2. 计费单价一致

`reasoning_content` 和 `content` 都按 **output token 的单价** 收费，费率完全相同，不存在折扣或优惠。

### 3. 如何查看拆分数据

API 返回的 `usage` 对象中包含 `completion_tokens_details`，可以细看：

| 字段 | 含义 |
|---|---|
| `completion_tokens` | 输出 token 总数（reasoning + answer 合并） |
| `completion_tokens_details.reasoning_tokens` | 思维链（reasoning_content）的 token 数 |
| `completion_tokens - reasoning_tokens` | 最终答案（content）的 token 数 |

```json
"usage": {
  "prompt_tokens": 120,
  "completion_tokens": 2340,           // 合并计数
  "total_tokens": 2460,
  "completion_tokens_details": {
    "reasoning_tokens": 2100            // 思维链部分
    // 剩余 240 即 content 的 token 数
  }
}
```

### 4. 实际影响

思维链（reasoning_content）通常远长于最终答案（content），尤其是数学、代码等需要多步推理的任务。如果你只按 UI 上看到的 `content` 来估算成本，会**严重低估**实际账单。

---

**总结**：你说的完全正确——`completion_tokens` = `reasoning_content` token 数 + `content` token 数，两部分合并按 output 单价计费。如果想精确追踪，可以在 API 响应的 `usage.completion_tokens_details.reasoning_tokens` 字段查看思维链的实际 token 消耗。

## 结论：DeepSeek **确实** 单独暴露了 reasoning token 的统计数据

根据 [Chat Completions API 文档](https://api-docs.deepseek.com/api/create-chat-completion) 中的 Schema 定义，`usage` 对象的结构如下：

### 官方 Schema（精确引用）

```
usage
├── completion_tokens          integer   // 生成completion的总token数
├── prompt_tokens              integer   // 输入token数 = cache_hit + cache_miss
├── prompt_tokens_details
│   ├── cached_tokens          integer
│   ├── prompt_cache_hit_tokens integer
│   └── prompt_cache_miss_tokens integer
├── total_tokens               integer
└── completion_tokens_details
    └── reasoning_tokens        integer   // ← 模型推理过程消耗的token数
```

关键字段的定义原文：

> **`completion_tokens`** — Number of tokens in the generated completion.
> **`completion_tokens_details.reasoning_tokens`** — Tokens generated by the model for reasoning.

### 也就是说

| 你想知道的内容 | 字段 | 公式 |
|---|---|---|
| reasoning_content 的 token 数 | `usage.completion_tokens_details.reasoning_tokens` | 直接读取 |
| content（最终答案）的 token 数 | — | `completion_tokens - reasoning_tokens` |
| 两者合计（计费总量） | `usage.completion_tokens` | 直接读取 |

**`completion_tokens` 确实不区分**，它是 `reasoning_content + content` 的合并值。但通过 `completion_tokens_details.reasoning_tokens` 可以精确拆分出思维链部分占了多少。

### 回到你的问题

> "是否能够找到其实思维链是没有单独计算的token数据的呢？"

**不能。** 官方文档明确显示，DeepSeek API **已经** 单独记录了 `reasoning_tokens`，你可以在每次 API 响应的 `usage.completion_tokens_details.reasoning_tokens` 中直接查到思维链的 token 消耗，而不是只有一笔合并的 `completion_tokens`。
