```md
# 粗筛阶段缓存优化策略对比

## 当前策略（推测）

每次调用发送不同的词子集，导致缓存命中不稳定：

```
call-0001: 问题 + 指令 + 词表[1-373]   → 输入3642 tokens (未命中186, 命中3456)
call-0002: 问题 + 指令 + 词表[1-372]   → 输入3665 tokens (未命中209, 命中3456)
call-0046: 问题 + 指令 + 词表[8个]     → 输入143 tokens (未命中143, 命中0)
```

**问题**：
- 词表内容每次都不同，缓存无法完全命中
- 平均每次未命中 197 tokens
- 644次调用总计未命中 127,043 tokens

---

## 优化策略（你的提案）

### 核心思想
**第一次调用建立完整缓存基线，后续调用在基线上追加少量新内容**

### 具体实现

**第一次调用（建立缓存基线）：**
```
问题 + 指令 + 【全量去重名词表 1-3373】

注意：这里要求 LLM 对所有词筛选一遍，建立完整缓存
```

**第 2-N 次调用（分批查询，前面全部命中缓存）：**
```
问题 + 指令 + 【全量去重名词表 1-3373】 + 分隔符 + 当前批次[1-100]
问题 + 指令 + 【全量去重名词表 1-3373】 + 分隔符 + 当前批次[101-200]
问题 + 指令 + 【全量去重名词表 1-3373】 + 分隔符 + 当前批次[201-300]
...
```

### 缓存命中分析

**第一次调用：**
- 输入：~10,000 tokens（问题+指令+全量3373个词）
- 缓存未命中：10,000 tokens
- 缓存命中：0 tokens

**第二次及以后每次调用：**
- 输入：~10,000（缓存基线）+ ~300（当前批次100个词）= 10,300 tokens
```
